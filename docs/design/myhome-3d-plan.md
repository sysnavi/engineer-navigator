## 1. 試作でできたこと

- ホームの島と同じ描画部品 `StageScene` に、2 つの段を足しただけで部屋になった（`src/lib/home/stage.ts` の `layer`）。
  - `layer: "floor"`: 床に敷くもの（ラグ）。いつも一番奥に描く。
  - `layer: "wall"`: 壁。**手前側に回ってきた壁は描かない**（カットアウェイ）。どの向きでも、奥の 1〜2 面の壁だけが見える。
- 部屋の大きさは、最初の試作で床 64×48・壁の高さ 26（ボクセル）。広さの比べは 1b。家具 7 点（本棚・テレビ・ソファ・ラグ・観葉植物・ランプ・冷蔵庫）とペット 3 匹（タローガエル・チョコスライム・サワーおばけ）。
- ◀ ▶ と横スワイプで 8 方向に回る。家具の陰に入ったペットは、島と同じシルエットで見える。ペットはまばたきし、タップで跳ねる。
- 並べ方は `src/lib/home/room3d.ts`、原本は `scripts/gen-room-vox.ts` が起こした試作の .vox（`public/stack/room/`・`furniture/`・`gadget/`）。
- 画像（スマホ 375px・PC 1280px の 8 方向）は報告フォルダ（`sprite-stack/myhome-3d/`）。

分かったこと:
- 家具の大きさは、LIVING.sav の `size`（ペット = 10）の比を保ったまま 8 割に縮めると、狭い箱庭に収まる。ペットが少し大きく見えて、かわいい。
- 整数倍の拡大（1 倍・2 倍）では、本棚がペットより小さいか、部屋に入らないほど大きいかのどちらかになった。端数の倍率（最近傍）にした。
- PC 幅（6 倍）では、斜めの向きで壁の上が枠に近い。本実装では、部屋の高さから拡大率を決める。

## 1b. 広さと見せ方（2026-11-28 追加。オーナーの感想「いいかんじやね。でも狭すぎるかな」を受けて）

試作の `/explore/myhome-3d?size=xs|s|m|l` で、同じ家具 7 点・ペット 3 匹のまま広さを変えて比べた。家具は壁ぎわ・すみに寄せ、真ん中を空けた（`src/lib/home/room3d.ts` の `roomLayout`）。

| 広さ | 床（ボクセル） | 今の 2D の「へやの広さ 3 段」との対応 |
|---|---|---|
| xs | 64×48 | 最初の試作（狭すぎる） |
| s | 96×64 | 拡張なし |
| m | 112×72 | 拡張 1 |
| l | 128×80 | 拡張 2 |

2D の広さは横幅が 1.0 / 1.5 / 2.0 倍になる。3D は横と奥行きの両方が広がるので、横幅は 1.0 / 1.17 / 1.33 倍でも、床の面積は 1.0 / 1.31 / 1.67 倍になる。広くなった感じは十分に出る。

広くしてもスマホで小さくなりすぎないための工夫（どれも `StageScene` の任意の設定。島には影響しない）:
1. **拡大率を画面の実際の画素で刻む**: 1 倍刻みではなく、Retina なら 2.33 倍・2.67 倍なども使う。ドットはそろったまま。
2. **向きごとに、部屋がちょうど入る拡大率にする**（`layout.room`）: 横長の部屋を縦長の画面で見るとき、長い辺が奥へ向く向き（横）では大きく出せる。
3. **縦長の画面では、見下ろす角度を深くし（傾き 0.55 → 0.72）、最初の向きを「横」にする**（`portraitPitch`・`portraitDir`）: 部屋の長い辺が画面の縦に沿って、縦長の枠いっぱいに使える。
4. **寄る**: ＋ − ボタンとピンチで 3 段まで寄れる。寄ったら、ドラッグで部屋を見回す。ペットをタップしても寄らない（おせわメニューだけ。オーナーの確認で「いらん」となった）。
5. **ペットが歩き回る**（`wander`）: 家具をよけて、床の空いた所をゆっくり歩き、ときどき立ち止まる。進む向きを向いて歩く。広い部屋の余白が「ペットの散歩道」になって寂しくない。

スマホ（幅 375px・3 倍の画面）でのペットの大きさ（16 ボクセル × 拡大率）:

| 広さ | 正面 | 横（縦長の画面の最初の向き） | ＋1 寄る |
|---|---|---|---|
| xs 64×48 | 約 64px | 約 69px | — |
| s 96×64 | 約 48px | 約 64px | 約 80px |
| m 112×72 | 約 43px | 約 59px | 約 75px |
| l 128×80 | 約 37px | 約 53px | 約 69px |

**おすすめ: 拡張なしを 96×64 にし、拡張ごとに 112×72 → 128×80 と広げる。スマホは縦長の向き（横）から始め、ペットをタップして寄れるようにする。**
- 理由:
  - 96×64 は、最初の 64×48 の床の 2 倍の広さ。家具を壁ぎわに並べても、真ん中にペットが歩ける場所が残る。
  - スマホの最初の向きでは、ペットが今の LIVING.sav（48px 前後）より大きく見える。
  - 今の「へやの広さ 3 段」にそのまま対応するので、拡張キットのごほうびも 3D で感じられる。
  - 一番広い 128×80 でも、最初の向きで約 53px、寄れば約 69px。小さすぎない。
- 気になる点:
  - 向きごとに拡大率を変えると、回すたびに寄り引きする（PC の横長の画面では、正面が大きく、横・斜めが小さい）。本実装では、拡大率の切り替えを短いアニメーションにするか、縦長・横長ごとに 1 つの拡大率に固定するかを決める。
  - 縦長で傾きを深くすると、家具を少し上から見る形になる。比べると、平らな角度（`?pitch=flat`）より床が広く見えて、ペットの位置も分かりやすい。

## 3. 今の操作が、回る部屋でどうなるか（案）

前提: **データ（DB）は変えない**。家具の位置は今の「横 % ＋ 段（wall / shelf / floor）＋ 縦 %」のまま。3D では、それを部屋の座標に読み替える。
- floor の家具: 横 % → 部屋の左右、縦 % → 部屋の奥行き（下ほど手前）
- wall の家具: 奥の壁の左右の位置
- shelf の家具: 奥の壁の棚の上

これで 2D と 3D を同じデータで行き来でき、戻すのも簡単になる。

| 操作 | 今（2D） | 回る部屋での案 |
|---|---|---|
| 家具を動かす | ドラッグ（% 座標） | ドラッグ。画面の点を、床の座標に逆算する（今の向きの回転を戻すだけ）。段ごとに動ける範囲を床・壁・棚に絞る。**動かしている間は回せない**ようにする |
| 家具を置く（収納 BOX から出す） | 収納 BOX の一覧から出すと既定の位置に | 同じ。今の向きの手前寄りに出す（すぐ見つかるように） |
| しまう | 右下の「📦 しまう」へドロップ | 同じく画面の隅の箱へドロップ。部屋が回っても、箱は画面に固定する |
| 収納 BOX | 部屋の下に一覧 | そのまま（2D の UI でよい。3D の中に入れない） |
| ペットの「出かけ中」 | 「◯◯はデスクへおでかけ中」の札 | 札はそのまま。加えて、**デスクの部屋に行っている子は、デスクの部屋で 3D で見える**（同じ箱庭の部品で、DESKTOP.sav も部屋にする場合） |
| なまえの一覧 | 部屋の下の一覧 | そのまま（2D）。一覧のペットを押すと、部屋の中のその子が跳ねる（どこにいるか分かる） |
| ペットのくつろぎ（ソファに座る・ラグで寝る） | 家具の上の決まった位置へ | 家具ごとの「座る所」を 3D の座標で持つ（`petSpot` に高さを足す）。座っている子が陰に入ったら、シルエット |
| 壁紙・床（もようがえ） | CSS の色 | 壁・床の .vox を模様ごとに用意して差し替える |
| 部屋の広さ（拡張キット） | 横に広がる | 床と壁の幅を 3 段で変える（.vox を 3 種類）。広いほど拡大率を下げる |

手前の壁は描かないので、家具を壁ぎわに置いても見えなくならない。ペット・家具のタップと長押しは、今の当たり判定（`hitTest`）がそのまま使える。

## 4. つながり：ホームの島から家に入る（案）

1. ホームの島の家をタップすると、家に寄っていく（カメラが家に近づく短い動き）。
2. 部屋（この箱庭）に切り替わる。**島で向いていた向きのまま**部屋に入ると、つながって見える。
3. 部屋の左上に「← 島へ」のボタン。島に戻ると、家の前に主役が立っている。

画面の作りは、ホーム（`/`）の舞台を「島」と「部屋」で切り替える形がよい。URL は `/home`（マイホーム）のままにして、島の家から `/home` に入る。家の中では、今の DESKTOP.sav と LIVING.sav を「デスクの部屋」と「リビング」の 2 部屋として、横に並べる（または部屋の中のドアで行き来する）。

## 5. 段階 3・4 との順番と工数（おすすめ）

| 順 | 中身 | ざっくりの工数（このセッションの作業の量） |
|---|---|---|
| **1** | **マイホームの箱庭（リビングだけ）**: 表示・回す・家具とペットのくつろぎ・壁紙と床・広さ。ドラッグで動かす・しまう・置く | 3〜4 日 |
| 2 | 家具の手直し 6〜8 点、ガジェットを寝かせる変換、デスクの部屋（DESKTOP.sav）の箱庭化 | 2〜3 日 |
| 3 | 島から家に入るつながり（カメラの動き・行き来） | 1 日 |
| 4 | 段階 3: おさんぽの島（ビオーム 18。1 つずつ島を作る） | 1 つ 0.5〜1 日 × 18（まず 3〜4 個で区切る） |
| 5 | 段階 4: ダンジョンの見下ろし化（部屋の連なり・移動・戦闘の見せ方） | 1〜2 週間（ゲームの作りが変わるので一番大きい） |

おすすめの理由:
- マイホームは、ホームの島と**同じ部品で作れる**ことが試作で分かった。足したのは「床の段」と「手前の壁を消す」だけ。素材も 8 割以上が自動で起こせる。一番早く、目に見える成果が出る。
- 毎日開く画面なので、3D の手ざわりを一番多く見てもらえる。
- 段階 3（おさんぽ）は、ビオームの数が多い。マイホームで作る「床・壁・模様をプログラムで起こす」仕組みが、そのまま島の地面づくりに使える。だから後にしたほうが速い。
- 段階 4（ダンジョン）は、見せ方だけでなく遊び方が変わる。オーナーの判断（部屋のつなぎ方など）が要るので最後に。

## 6. 決めてほしいこと（判断が要る点）

1. **リビングだけ先に**箱庭にするか、デスクの部屋も同時か（おすすめ: リビングだけ先に）。
2. **2D の部屋を残すか**（おすすめ: しばらく「2D で見る」の切り替えを残す。データは共通なので、どちらでも同じ部屋になる）。
3. 家具の向き: 今の絵はすべて正面向き。3D では、壁ぎわの家具は部屋の内側を向くように回したい。家具ごとに向きを持たせるか（データに「向き」を足すことになる。これだけは DB の変更が要る）。
4. 家具の手直し（6〜8 点）を MagicaVoxel で人が直すか、生成スクリプトに形を書き足すか。
5. ガジェットの「机に寝かせる」は、絵を新しく描くか（真上から見た絵）、変換で寝かせるか。
