# 実装ワークフロー

依頼を受けてからコミットまでの標準手順。飛ばしていいステップはない。

## 0. 環境を検知する

最初に一度だけ判定し、以降の手順を分岐する:

```bash
nc -z localhost 5433 && echo "DB: あり（フル検証モード）" || echo "DB: なし（クラウドモード）"
```

- **フル検証モード**（ローカル・DBあり）: E2Eまで手元で回す
- **クラウドモード**（claude.ai/code等・DBなし）: `npm run check` までを手元のゲートにし、
  E2Eは push 後の CI に委任する。**push後にCIを見届けるところまでがタスク**（/release 参照）

## 1. 依頼を分類する

- **デザイン・レイアウト調整**: ブラウザでの目視確認が本来必須。クラウドモードでは
  「CSSの明白な修正」だけ対応し、微調整が要るものは修正案をコミットせず提示に留めるか、
  ローカル作業を提案する
- **フォーム・スキーマ・週報関連**: 対応する docs（roadmap / weekly-report / data-model）を
  先に読む。設計思想に反する変更は実装前に指摘する
- **Next.js の機能に触れる**: `node_modules/next/dist/docs/` の該当ガイドを先に読む
  （このプロジェクトの Next 16 は学習データと挙動が違う前提で扱う）

## 2. 実装の決まりごと（AGENTS.md の要点チェックリスト）

- [ ] LLM呼び出しは必ず `src/lib/ai/client.ts` 経由
- [ ] EngineerSkill を直接書き換えない（SkillSuggestion → 本人承認フロー経由）
- [ ] 顧客実名をDBに入れない（`Project.clientAlias` のみ）
- [ ] `ANTHROPIC_API_KEY` 未設定でも機能自体は失敗させない（解析だけFAILEDが流儀）
- [ ] 画面外のクライアントコンポーネントは遅延ハイドレーションでマウントされない。
      初回タップで必ず動くべき処理はインラインスクリプトで書く
- [ ] マイグレーションを追加したら、稼働中の dev サーバーを再起動する
      （新カラムが undefined になるのは古いPrismaクライアントが原因）

## 3. 検証する

```bash
npm run check        # 型 + lint + ユニット。両モード共通・必須
```

フル検証モードではさらに:

```bash
npm run test:e2e     # スモーク全体（専用DBなので開発DBは無事）
```

- 触った導線がスモーク5本（ホーム/週報/今日の一問/スキルマップ/ウェルカム）の
  対象外なら、ブラウザ（preview）で実際に操作して確認する
- **機能ツアー（日次トリアージの検出部・tests/tour/tour.spec.ts）を追従させる**:
  - 画面（page.tsx）を足したら `tour("<画面名>", ...)` を1本足す。忘れると `npm run check` の
    網羅ガード（tests/tour/coverage.test.ts）で止まる
  - 既存画面の導線・見出し・ボタン文言を変えたら、その画面のツアーを1本だけ回す:
    `TOUR_ONLY=<id> npm run test:tour`（idは tour() の第1引数）。落ちたら同じPRで直す
    （スモークを同じPRで直すのと同じ流儀。放置しても翌朝のルーティンが「ツアー修正PR」を出すが、
    自分で直すほうが早い）
- **機能や入口を足したら TIPS集（src/lib/tips.ts）に1件足す**。右下に出る豆知識は
  新機能の発見率を上げる導線なので、載せ忘れると「TIPSが古い」状態になる（2026-09に
  8月以降の機能が丸ごと抜けていた）。数値（EXP・日数）は src/lib/exp.ts 等の定数と合わせる。
  href の実在は src/lib/tips.test.ts が `npm run check` で見る
- 純ロジックを追加・変更したら、併置のユニットテスト（`src/**/*.test.ts`）も更新する
- 壊れやすい境界（日付・レベル閾値・決定性）を触ったら回帰テストを足す

## 4. コミットする

- メッセージは日本語で「エリア: 何をどうした（なぜ）」形式。既存の git log の流儀に合わせる
- 無関係な変更を混ぜない（別件に気づいたらその旨だけ報告して別タスクにする）
- **push はこのskillの範囲外**。リリースは /release の手順で行う
